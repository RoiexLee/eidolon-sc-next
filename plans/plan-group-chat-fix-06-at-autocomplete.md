# 群组对话修复 06：输入 `@` 自动选择群组成员

Status: done

## 问题

群聊输入栏当前始终显示一个「选择回复对象」的 `Select`，用户必须先打开选择框；输入框本身没有检测 `@`、候选成员弹层或插入目标的逻辑。这和附图所示的“输入 `@` 后在输入框上方选择成员”不一致。

## 当前契约与待确认边界

后端 `GroupTurnInput.mention_character_ids` 当前最多接受一个成员，`GroupTurnEngine` 也按单一目标生成回复。附图里的「@ 全体成员」与“选择一个成员”的文字要求不一致，也不能直接接入现有 API。

本票默认先实现**单成员 `@`**：候选只列当前成员，发送时继续提交一个规范化的 `mention_character_ids`。`@ 全体成员` 另由票 07 处理，避免把后端多目标回复和输入体验混在同一票里。

## 目标

- 移除常驻的目标 `Select`。
- 用户在文本框输入 `@` 后，紧贴输入栏弹出当前群组成员候选。
- 候选支持鼠标/触控和键盘上下选择、回车确认、Esc 关闭；高亮当前候选并显示角色缩略图和名字。
- 选择后插入 `@角色名`，继续允许用户编辑其余文本；发送时把选择的角色 id 放入 `mention_character_ids`。
- 引用消息仍自动指定其作者；没有 `@`/引用时保留现有轮流回复语义，但不再通过可见 Select 暴露。

## 设计与实现

1. 在 `GroupConversationView.tsx` 管理输入光标、最后一个 `@` token、候选查询、候选索引和已选目标 id；只在当前 token 位于光标前且发送未进行时打开候选。
2. 复用项目已有 `MarkedAvatar`、按钮状态和暗色 token；候选列表以内联绝对定位贴在原生 `Textarea` 上方，避免引入第二个输入控件并保留输入焦点。
3. 选择成员时用最小的文本替换逻辑将 token 替换为 `@成员名 `，同步目标 id；删除或编辑该 token 后清空目标 id，避免发送过时的 mentions。候选过滤只按当前 `@` 后的文本，不修改用户其他文字。
4. 保持原生 `Textarea`，先把强调放在候选项高亮和已选目标状态上；不要为了给单个文本片段着色贸然换成 `contenteditable`。如果产品必须让输入框内的 `@角色名` 变蓝，需要另做输入层/高亮镜像方案，并专项验证光标、滚动和中文输入法。
5. 删除 `Select`、`MentionIcon` 目标选择状态和相关 placeholder 依赖。没有 `@` 或引用时提交空的 `mention_character_ids`，由后端继续执行轮流目标；有引用时使用引用作者；有 `@` 时使用候选对应的单个成员 id。发送按钮只按文本和发送状态判断，后端仍校验成员归属和单目标限制。

## 影响范围

- `frontend/src/components/conversations/GroupConversationView.tsx`
- `frontend/src/lib/api.ts` 发送类型保持单成员契约
- 必要时新增 `frontend/src/lib/groupChat.ts` 的 token 解析辅助及测试
- 可能补充 `frontend/src/i18n/zh.ts` 的候选、关闭和无结果文案
- 不改 `backend/src/eidolon/group_api.py` 的单目标契约

## 验收与测试

- 输入 `@` 自动打开成员候选；输入拼音/文字可过滤，选择后能继续输入并正确发送。
- 键盘上下、回车、Esc、鼠标/触控和中文输入法组合输入不丢字、不误提交。
- 选择后删除 `@` token 不会残留旧的 `mention_character_ids`；引用消息与 `@` 冲突时沿用现有服务端错误。
- 群成员增删后候选只包含当前成员；发送中、通话中和弹层关闭时焦点行为明确。
- 运行相关 Vitest、typecheck、discipline；本地构建版用 Playwright 验证附图的输入前/输入 `@` 后状态。

## 不在本票

- 不实现 `@ 全体成员`、多成员同时回复、回复次数/“剩余次数”展示；这些由 `plan-group-chat-fix-07-at-all-members.md` 单独设计。
- 不改主动回复轮流规则、群组提示词或群组通话。

## 实现结果

移除常驻目标 `Select`。原生 `Textarea` 在光标所在位置输入 `@` 后显示当前群组成员候选，支持按名字、中文名、假名和罗马字过滤；候选支持鼠标、上下键、回车和 Esc，选择后插入 `@角色名 ` 并提交单个成员 id。没有提及时提交空目标，引用消息仍由后端使用引用作者。输入内容不做变色，也没有迁移到富文本编辑器。

## 验证结果

已通过群组工具测试、前端 typecheck、discipline 检查和受影响测试；真实浏览器中的输入法和视觉验收留给本地构建版检查。
